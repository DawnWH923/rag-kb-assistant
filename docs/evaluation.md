# RAG 评测基准（三层）

只看"答案好不好"无法归因——问题可能出在检索没召回、精排排错、或生成跑偏。本仓库按三层分别评测：

## 层 1：召回（该出现的文档进没进来）

- 指标：recall@8（向量召回候选数 = 8，见 `api.py` / `rerank.py`）
- 方法：评测集每条标注"期望命中的文档/章节"，统计其是否进入召回候选
- 失败特征 → 切分问题（块切太碎/太大）、Embedding 语言不匹配

## 层 2：精排（最相关的排到最前了吗）

- 指标：Cross-Encoder 精排后 top-4 中首位的正确率（MRR 可选）
- 方法：对召回候选人工标注相关度，看 BGE-reranker 是否把相关块顶到前 4
- 失败特征 → 精排模型不匹配语域、（问题, 文档）拼接方式不佳

## 层 3：答案（基于对的材料答对了吗）

- 指标：要点命中率 + 引用正确率；**拒答正确率**（上下文不足时说"不知道"而非编造）
- 方法：人工判分为主，可叠加 LLM 判分并核对两者一致率
- 失败特征 → Prompt 约束不足、上下文组装丢失关键块

## 评测集构建

1. 来源：真实用户高频问题 + 边界问题（跨章节、含专业术语、含糊提问）；
2. 每条标注：期望命中文档、期望答案要点、问题类型；
3. 用途：**每次改切分参数、改 recall_k、改 rerank 模型后全量回归**。

## 当前实现参数（与代码一致）

| 环节 | 参数 | 位置 |
|------|------|------|
| 向量召回 | top-8（双塔，快但粗） | `api.py` |
| 精排 | Cross-Encoder 取 top-4（慢但准） | `rerank.py` |
| 生成 | DeepSeek-Chat，上下文不足拒答 | `api.py` PROMPT |
